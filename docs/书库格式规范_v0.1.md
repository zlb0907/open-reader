# 书库格式规范 v0.1

> 面向「免费、离线、开放的个人电子书阅读器」。桌面端先行，后续 Android 端读写同一份书库。
> 本规范与编程语言、UI 框架无关，是各端共同遵守的数据契约。**先定规范，再写代码。**

## 1. 设计原则

1. **开放可读**：不用私有加密容器，文本编辑器 / SQLite 工具都能直接打开。
2. **原件不改写**：导入时原样复制，程序生成的都是可重建的派生物。
3. **索引可丢弃**：`search.db` 丢了能重建，不参与同步，不作为唯一副本。
4. **平台无关**：相对路径、UTF-8、UTC 时间、UUID 身份；不绑定机器码、注册表或任何 OS 标识。
5. **写冲突最小化**：一本书一个文件，避免"全库一个数据库"被多端同时写。
6. **无账号、无服务器**：同步交给用户自己的云盘 / WebDAV / Syncthing / 局域网。

## 2. 目录树

```
MyLibrary/
├─ library.json              库级信息与版本（低频写）
├─ collections.json          书架树 / 分类（低频写）
├─ settings.json             阅读偏好，随库走（可选）
├─ books/
│  └─ <book-uuid>/
│     ├─ source.<ext>        原件，原文件名存 meta.json
│     ├─ meta.json           书目 + 章节表 + 进度 + 书签（一书一文件）
│     └─ cover.jpg           可选，可重建
└─ .index/
   └─ search.db              SQLite + FTS5，本地索引，可丢弃、不同步
```

`.index/` 明确标记为派生物，是规避多端 SQLite 并发写冲突的关键。

## 3. 文件定义

### 3.1 library.json

```json
{
  "format": "open-library",
  "schema_version": 1,
  "library_id": "3f8c...",
  "name": "我的书库",
  "created_at": "2026-11-13T06:00:00Z",
  "updated_at": "2026-11-13T06:00:00Z"
}
```

书籍清单**不放在这里**：每本书自己一个 `meta.json`，扫描 `books/*/meta.json` 即得到清单，天然避开单点并发写。

### 3.2 collections.json

```json
{
  "updated_at": "2026-11-13T06:00:00Z",
  "root": [
    { "id": "c1", "name": "小说", "children": [], "hidden": false },
    { "id": "c2", "name": "私密", "children": [], "hidden": true }
  ]
}
```

`hidden` 只是 UI 隐藏标记，**不加密、不承诺安全性**（与原软件的"带密码隐藏文件夹"刻意不同，避免给用户虚假的安全感）。

### 3.3 books/&lt;uuid&gt;/meta.json

```json
{
  "id": "b1-uuid",
  "title": "书名",
  "author": "作者",
  "original_filename": "三体.txt",
  "format": "txt",
  "encoding": "utf-8",
  "size_bytes": 123456,
  "sha256": "…",
  "collection_ids": ["c1"],
  "tags": [],
  "added_at": "2026-11-13T06:00:00Z",
  "updated_at": "2026-11-13T06:00:00Z",
  "revision": 1,
  "chapters": [
    { "id": "ch-uuid", "index": 0, "title": "第一章",
      "locator": { "kind": "txt_offset", "start": 0, "end": 20480 } }
  ],
  "progress": {
    "chapter_id": "ch-uuid", "percent": 0.42,
    "locator": { "kind": "txt_offset", "offset": 8600 },
    "updated_at": "2026-11-13T06:00:00Z"
  },
  "bookmarks": [
    { "id": "bm-uuid", "chapter_id": "ch-uuid", "offset": 3200,
      "note": "", "created_at": "…", "updated_at": "…", "deleted_at": null }
  ]
}
```

`locator.kind` 是格式中立的关键字段，不要把 TXT 的字节偏移硬编码成通用结构：

| kind | 适用 | 字段 |
|---|---|---|
| `txt_offset` | TXT / 纯文本 | `start` / `end` / `offset`（字符偏移，非字节） |
| `epub_spine` | EPUB | `spine_index` + `cfi` 或 `anchor` |
| `pdf_page` | PDF | `page` + `char_offset` |
| `docx_paragraph` | DOCX | `paragraph_index` |

### 3.4 .index/search.db

```sql
CREATE TABLE books (
  id TEXT PRIMARY KEY, title TEXT, author TEXT,
  meta_path TEXT, updated_at TEXT, revision INTEGER
);
CREATE TABLE chapters (
  id TEXT PRIMARY KEY, book_id TEXT, idx INTEGER,
  title TEXT, start_offset INTEGER, end_offset INTEGER
);
CREATE VIRTUAL TABLE book_fts USING fts5(
  title, author, body, tokenize = 'unicode61'
);
```

`reindex` 命令扫描 `books/*/meta.json` + 原件全文，重建整库索引。必须支持**增量**（按 `updated_at` / `revision` 只处理变更的书），Android 端尤其不能启动时全库重建。

## 4. 冲突与同步规则

多端通过云盘 / Syncthing 同步同一个目录，不做服务端合并。约定：

| 对象 | 规则 |
|---|---|
| `books/*/meta.json` | `updated_at` 新者胜；`revision` 每次写入 +1 用于检测落后写 |
| `progress` | `percent` 大者胜；相同取 `updated_at` 新者（阅读进度只前进不回退） |
| `bookmarks` | 按 `id` 取并集，`deleted_at` 作墓碑，定期压缩清理 |
| `collections.json` | 整文件 last-write-wins（改动频率低，可接受） |
| `source.<ext>` | 用 `sha256` 校验；不一致时保留双份并提示用户，**绝不静默覆盖** |
| `.index/` | 不同步、不备份，各端本地重建 |

个人使用场景下，LWW + 并集足够，**不要引入 CRDT**，那是过度设计。

## 5. 导入与导出

- **单本导入**：复制原件到 `books/<uuid>/source.<ext>`，生成 `meta.json`，触发增量索引。原文件留在原处不动。
- **单本导出**：直接指向原件路径；或另存为 TXT / EPUB（导出是一等公民，不是付费点）。
- **整库导出** `export-library`：打包为标准 zip（建议后缀 `.openlib`），含 `library.json`、`collections.json`、`books/**`；排除 `.index/` 与封面缓存。
- **整库导入** `import-library`：解包 → 校验 `schema_version` → 冲突合并 → 重建索引。
- 整库包必须是**平台无关**的：桌面导出的 `.openlib`，Android 能直接导入，反之亦然。

## 6. 路径、编码、命名约定

- 库内路径一律**相对**、正斜杠 `/`，禁止绝对路径与盘符。
- 磁盘文件名用 `<uuid>.<ext>`（小写扩展名，ASCII 安全）；用户可读的原始文件名存 `original_filename`。避开 Windows 非法字符、大小写不敏感、长度限制与 Android 文件名差异。
- 文本统一 **UTF-8 无 BOM**，换行 `LF`；导入时做编码检测并转码，转码结果写入 `derived/`，原件仍保留。
- 时间统一 **UTC ISO 8601**（`2026-11-13T06:00:00Z`），展示层再按本地时区格式化。
- 不加密、不混淆、不绑定硬件 ID。

## 7. Android 适配要点

- **库位置二选一**：应用外部私有目录 `Android/data/<pkg>/files/`（免权限，最省事），或 SAF `ACTION_OPEN_DOCUMENT_TREE` 授权的共享目录（才能和桌面端共用云盘文件夹）。
- 共享目录返回的是 `content://` URI，**不能用 `File(path)` 硬读**。实现里抽象一层 `StorageBackend`：`desktop` 走普通文件系统，`android` 走 `DocumentFile` / `ContentResolver`。这层是各端唯一的平台相关代码。
- **不申请 `MANAGE_EXTERNAL_STORAGE`**：Play 上架会被拒，且对阅读器没必要。
- 大文件走流式读取，别一次性读进内存；索引增量重建放后台任务，注意电量与内存限制。
- 分发：自签名 APK，GitHub Releases / F-Droid；无账号、无内购、无更新服务器。

## 8. 版本与迁移

- `schema_version` 单调递增。读到更高版本时**拒绝写入**并提示升级，不静默降级。
- 迁移脚本放 `migrations/`，单向、幂等，执行前自动备份 `books/*/meta.json`。
- 任何字段新增都用可选字段，旧版本实现忽略未知字段即可继续读。

## 9. 各端实现检查清单

**桌面端**
- [ ] 能创建 / 打开 / 移动任意位置的库目录，路径可配置
- [ ] `reindex` 支持全量与增量
- [ ] 导出 `.openlib` 与单本 TXT/EPUB
- [ ] 不写注册表、不写库目录之外的用户数据

**Android 端**
- [ ] 通过 SAF 选择库目录并持久化 URI 权限
- [ ] 能导入桌面端导出的 `.openlib`
- [ ] 后台增量索引，可中断可恢复
- [ ] 触摸翻页、横竖屏、系统字体缩放、深色模式
- [ ] 一键整库导出（手机更容易丢数据）

**共同**
- [ ] 同一份库目录两端交替打开，进度 / 书签按第 4 节规则正确合并
- [ ] 删掉 `.index/` 后功能不受影响，仅搜索暂时不可用直至重建
